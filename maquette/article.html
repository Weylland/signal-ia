Magistral 2 : l'ouverture comme arme économique

Le laboratoire français publie les poids complets de son nouveau modèle de raisonnement, avec un coût d'inférence divisé par trois. Une stratégie d'ouverture radicale qui rebat les cartes pour les développeurs européens — et met la pression sur les API propriétaires.

L'essentiel — 3 points
  1. Mistral publie les poids complets sous licence Apache 2.0, y compris la variante 70B optimisée raisonnement.
  2. Le coût d'inférence est divisé par trois par rapport à Magistral 1, grâce à une architecture MoE avec 14B paramètres actifs sur 70B.
  3. Les benchmarks le placent au niveau d'o4-mini sur le code et les maths — mais auto-hébergeable, sans API externe.

En publiant l'intégralité des poids de Magistral 2 ce jeudi, Mistral ne fait pas qu'un geste vers la communauté open source : le laboratoire parisien attaque directement le modèle économique des API propriétaires. Pour un développeur, la promesse est simple — un modèle de raisonnement de niveau frontière, hébergeable sur sa propre infrastructure, sans compteur de tokens.

La variante 70B repose sur une architecture en mélange d'experts revue, qui n'active que 14 milliards de paramètres par requête. C'est ce qui permet l'affirmation la plus commentée de l'annonce : un coût d'inférence divisé par trois, vérifiable puisque chacun peut le mesurer sur son propre matériel.

Une stratégie de distribution assumée

Le choix de la licence Apache 2.0 n'est pas anodin. Contrairement à des licences « open » plus restrictives, Apache 2.0 autorise l'usage commercial sans redevance et sans obligation de partager les modifications. Pour les entreprises qui cherchent à intégrer un LLM dans leur chaîne de traitement sans dépendre d'un tiers, c'est un signal fort.

« Nous ne construisons pas un modèle pour concurrencer OpenAI. Nous construisons une infrastructure que l'Europe contrôle. »

— ARTHUR MENSCH, PDG DE MISTRAL · CONFÉRENCE DE PRESSE, 12 JUIN 2026

L'architecture MoE (mélange d'experts) active sélectivement 14B paramètres sur 70B à chaque requête. L'effet est double : la capacité de raisonnement reste celle d'un modèle 70B dense, mais la vitesse et la consommation mémoire s'approchent d'un modèle 14B. Sur un serveur A100 standard, cela représente une économie mesurable à chaque appel.

L'écosystème, le vrai chantier

Reste la question de l'écosystème. Les premiers retours des équipes qui ont eu un accès anticipé pointent une intégration encore inégale avec les frameworks d'agents — en particulier LangGraph et Claude Code. Mistral promet des connecteurs officiels « dans les semaines qui viennent », mais la communauté n'attend pas : les premiers serveurs MCP non officiels étaient déjà en ligne moins de quatre heures après l'annonce.
